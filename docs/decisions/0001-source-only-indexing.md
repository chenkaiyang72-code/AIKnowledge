# ADR-0001：索引必须只扫描源码，禁止依赖编译

状态：Accepted
日期：2026-08-02

## 背景

AIKnowledge 面向体量巨大、更新频繁并且可能跨仓的真实研发代码。要求每个仓库先成功编译，会带来工具链、生成文件、依赖、目标架构、构建时长和权限等前置条件，索引延迟与运维成本无法接受，也无法覆盖所有分支和配置组合。

## 决策

所有正式索引流水线必须满足以下约束：

1. 只读取 Git 对象或源码目录，不执行仓库中的任何构建脚本和生成器。
2. 不把 `.config`、`compile_commands.json`、`Module.symvers` 或编译产物作为索引前置条件。
3. 不以 scip-clang、Clang compilation database 或“仓库可成功编译”为首版运行依赖。
4. Kconfig、Makefile、头文件、预处理条件和清单文件作为普通源码解析；保存条件表达式，不假设某个配置一定生效。
5. 任何不能仅凭源码唯一确定的引用、调用或类型关系，都必须保存为带来源与置信度的候选关系，查询结果必须显示歧义，不能冒充编译器事实。

## 准确性方案

无需编译不等于只做文本搜索。索引由以下直接扫描通道共同组成：

- Tree-sitter：函数、类型、声明、宏和语法块。
- 标识符索引：定义、声明和出现位置，结合语言作用域、签名、路径与链接属性做候选绑定。
- include/import 图：直接解析预处理指令和语言导入语句。
- Kconfig/Kbuild 图：解析配置依赖、目录进入条件、目标与源文件映射。
- 静态调用候选：从调用表达式和注册表/回调宏中提取，保留候选集合与置信度。
- 文档和跨仓契约：通过 API 名称、头文件、协议、配置键、manifest 和人工确认关系连接仓库。
- 查询时交叉验证：精确标识符、全文、结构、关系和语义召回互相支持，并返回源码证据。

关系置信度分为：

- `source_exact`：源码中可直接观察到的定义、声明、include 和显式绑定。
- `source_inferred`：基于作用域、签名或 AST 推断出的唯一候选。
- `ambiguous_candidate`：存在多个可能目标，必须向 AI 明示。
- `human_verified`：经过领域工程师确认的跨仓或动态关系。

## 更新策略

索引按文件内容哈希增量更新：未变化的 blob、语法块、标识符和关系直接复用；只重建变化文件以及由显式 include、Kconfig/Kbuild 或契约边确定的有限依赖范围。新 snapshot 验证完成后原子切换，因此快速更新不会阻塞现有查询。

## 影响

- 优点：无需准备构建环境，适合大仓、快更新、多分支和跨仓场景；索引任务安全且容易横向扩展。
- 代价：宏展开后的最终类型、所有条件编译结果和部分间接调用无法保证唯一解析。
- 处理方式：保存条件、候选和覆盖率；使用多路证据与人工知识提高准确性，而不是通过编译换取单一配置下的精确性。

本 ADR 是强制架构约束；其他文档若出现依赖 build profile、compilation database 或 scip-clang 的旧描述，以本决策为准并应立即修订。
